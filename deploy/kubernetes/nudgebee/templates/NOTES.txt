{{- if and .Values.nudgebee_secret (eq (toString (index .Values.nudgebee_secret "NEXTAUTH_DUMMY_CREDS_ENABLED")) "true") }}

⚠️  WARNING: NEXTAUTH_DUMMY_CREDS_ENABLED is set to "true". This
   username/password provider exists to bootstrap the first admin user
   (new sign-ins are gated by the bootstrap access check). The password is
   randomly generated on first install (or operator-set), but it is shared:
   anyone who knows it can sign in with any existing user's email,
   bypassing OAuth / LDAP / SSO. Disable it once your admin user and a
   real auth method are set up:

     helm upgrade {{ .Release.Name }} ... --set nudgebee_secret.NEXTAUTH_DUMMY_CREDS_ENABLED=false

   The default in values.yaml is intentionally `true` for the first-run
   bootstrap experience; production overlays should disable it explicitly.
{{- end }}

   RabbitMQ exporters are not being scraped: their ServiceMonitor and
   PrometheusRule objects are off by default so the chart installs on clusters
   without the operator CRDs. Turn them on with:

     helm upgrade {{ .Release.Name }} ... \
       --set postgresql.metrics.serviceMonitor.enabled=true \
       --set postgresql.metrics.prometheusRule.enabled=true \
       --set rabbitmq.metrics.serviceMonitor.enabled=true \
       --set rabbitmq.metrics.prometheusRule.enabled=true

   The same four values ship as values-monitoring.yaml inside the chart, if you
   install from a checkout or keep your own values file.
